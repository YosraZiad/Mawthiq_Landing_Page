# مَوْثِق — جسر الخبرة | صفحة استقطاب شركاء التأسيس والبناء
### Mawthiq Partner Recruitment Landing Page

صفحة هبوط تفاعلية عالية الاحترافية باللغة العربية، مصممة خصيصاً لمبادرة **مَوْثِق — جسر الخبرة** بهدف استقطاب شركاء مؤسسين ومساهمين يمتلكون عقلية البناء والمسؤولية لتحويل الفرص والحلول البرمجية إلى كيان تجاري مستقل ومستدام.

---

## 🏛️ المبادئ والقرارات التصميمية (Design & Product Principles)

1. **الهوية والتأسيس وليس التوظيف التقليدي**:
   - تم تصميم الصفحة لتبتعد تماماً عن صفحات التوظيف التقليدية أو اللوحات الإعلانية النمطية.
   - توضيح قاطع بأن الكيان التجاري الجديد مستقل قانونياً وتنظيمياً، دون الخلط بينه وبين كيان "مَوْثِق".
   - تجنب إطلاق أي وعود غير معتمدة بشأن الرواتب الثابتة أو نسب الملكية أو العوائد، مع إبراز أن كافة الترتيبات تُؤطر باتفاق رسمي مخصص في حينه.

2. **التوجه البصري التحريري (Editorial & High-Craft)**:
   - مستوحى من كبريات المنصات العالمية الرصينة (Linear, Stripe) مع الحفاظ على خصوصية الخط العربي والاتجاه من اليمين لليسار (`dir="rtl"`).
   - اعتماد خط **IBM Plex Sans Arabic** الرصين والمتزن للأوزان التحريرية والعناوين، مع خط **Cairo** كبديل مدعوم بنظام خطوط احتياطي متين.
   - مساحات بيضاء مدروسة، حدود دقيقة وخافتة (`slate-800` و `slate-850`)، وألوان وقورة (كحلي نيلي عميق، مع لمسات كهرمانية استراتيجية وأزرق مَوْثِق الهادئ).
   - تجنب المؤثرات المفرطة، التدرجات الذكاء الاصطناعي الفاقعة، والإيموجي التزييني المبتذل.

3. **تجربة مستخدم تفاعلية منضبطة**:
   - **الواجهة الرئيسية (Hero)**: تتضمن تمثيلاً بيانياً هيكلياً لمسار التحول (الفكرة → الاستراتيجية → التنفيذ البرمجي → الكيان المستدام)، مع مبدّل سياقي لشرائح الجمهور المستهدفة (التجاري، التقني، التشغيلي).
   - **التقييم الذاتي الاسترشادي (Self-Assessment)**: أداة تفاعلية هادئة تطرح الأسئلة الخمسة التأملية وتوفر خلاصة استرشادية دون ادعاء أنها اختبار علمي.
   - **نموذج التقديم متعدد الخطوات (Multi-step Form)**:
     - الخطوة الأولى: المعلومات الأساسية ومجال المساهمة.
     - الخطوة الثانية: التفكير التجاري، المشكلة المستهدفة، والقيمة المضافة.
     - الخطوة الثالثة: الالتزام الزمني، المسؤوليات المريحة، التوقعات، وإقرار الخصوصية.
     - حفظ تلقائي للمسودة في التخزين المحلي (`localStorage`) لضمان عدم ضياع إجابات المتقدمين.
     - رقم مرجعي فريد لكل طلب (`MWTQ-2026-XXXX`) ورسالة تأكيد واضحة.
   - **لوحة استعراض الطلبات للجنة الاستقطاب (Reviewer Inspection Drawer)**: زر عائم اختياري يتيح لأعضاء اللجنة ومسؤولي التأسيس استعراض الطلبات المسجلة تجريبياً محلياً وقراءة إجابات المتقدمين بتنسيق منظم.

## 🚀 التشغيل والتطوير (Getting Started)

### المتطلبات المسبقة:
- Node.js (الإصدار 18 فما فوق، تم التحقق على v22.18.0)
- npm

### تشغيل خادم التطوير المحلي:
```bash
npm run dev
```
سيتم فتح المشروع على `http://localhost:3000` (أو منفذ متاح).

### بناء نسخة الإنتاج:
```bash
npm run build
```
تُحفظ الملفات الجاهزة للنشر في مجلد `dist/`.

### معاينة نسخة الإنتاج محلياً:
```bash
npm run preview
```

## 🔌 ربط نموذج التقديم بالخادم الخلفي (Production Backend Integration)

تم تصميم المعمارية بحيث تكون مفصولة تماماً عبر ملف:
[`src/lib/applicationService.ts`](file:///d:/موثق-بزنس/Mawthiq%20Partnership%20Landing%20Page/src/lib/applicationService.ts)

### 1. في بيئة التطوير والعرض (Demo Mode):
- يعمل النظام تلقائياً على محاكاة الإرسال بشبكة واقعية مع تأخير زمني طبيعي.
- تُحفظ الطلبات في التخزين المحلي للمتصفح `localStorage` لتمكين لجنة المراجعة من فحص تجربة التقديم فوراً عبر زر "معاينة الطلبات" العائم.

### 2. في بيئة الإنتاج الحقيقية (Production API):
أنشئ ملف `.env` في جذر المشروع وضع عنوان واجهة برمجة التطبيقات (API Endpoint):
```env
VITE_API_ENDPOINT=https://api.mawthiq.com/v1/partner-applications
```
يقوم كود الخدمة تلقائياً عند وجود هذا المتغير بإرسال طلب `POST` مشفر بـ `JSON` يحتوي على:
- جميع حقول نموذج التقديم (الاسم، البريد، الرابط، المجال، إجابات التفكير، الالتزام الزمني، التوقعات).
- الطابع الزمني `submittedAt`.
- معلومات العميل `clientUserAgent`.
